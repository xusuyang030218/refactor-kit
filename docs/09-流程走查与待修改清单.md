## 三、待修改清单

### A 级：阻断流程（必须修）

**A1. 技术选型"请模型给建议"必然失败**
- 现象：面板点了按钮，模型一调用 `rk_tech_advise` 就报"未配置模型槽 strong"。
- 证据：`src/plugin/tools-project.js:295` 写死 `resolveSlot(p.config, 'strong')`；而 `src/core/detect.js` 的 `draftConfig` 只生成 `fast` 和 `reviewer` 两个槽。
- 实测：`strong: ✗ UNKNOWN_SLOT 未配置模型槽 strong。slots 中已有：fast、reviewer`
- 建议：`rk_tech_advise` 按 `strong → fast → 当前会话模型` 依次回退；同时 `draftConfig` 补上 `strong` 槽。

**A2. 模型槽"留空"与面板说明不符，导致分身/审查全废**
- 现象：面板写着"留空 = 沿用当前会话正在用的模型"，但留空后分身和异源审查都报错。
- 证据：`resolveSlot`（`src/plugin/runtime.js`）对空 `provider` 抛 `SLOT_PLACEHOLDER`；`draftConfig` 默认写的就是空串。
- 实测：`fast: ✗ SLOT_PLACEHOLDER`、`reviewer: ✗ SLOT_PLACEHOLDER`
- 影响：L2 任务的异源审查（底线②）无法满足 → 任务永远关不掉。
- 建议：二选一 —— ① `resolveSlot` 遇到空值返回"继承"（不报错，交给 DSH 继承当前会话模型）；② 面板保存配置时，把留空项自动填成当前会话的 provider/model。

**A3. 从零重构时没有可用的门禁 → 无法取证 → 任务关不掉**
- 现象：任务无法完成。所有构建/测试命令都被白名单拒绝。
- 证据：
  - `detectProject(targetRoot)`（`src/core/detect.js:25`）**只扫描存放目录**；你的存放目录是空的 → `gates: {}`、`commandAllowlist` 只剩兜底的 `git diff/log/status`。
  - 实测：`mvn -q test`→`denied`、`pnpm -r build`→`denied`、`node --test`→`denied`；唯一放行的 `git diff --stat` 是只读命令，证明不了功能。
- 影响：底线①要求"断言必须有 pass 证据"，没有门禁就永远拿不到证据。
- 建议（三条一起做）：
  1. 初始化时**同时探测老系统**的技术栈（老系统有 `pom.xml` 和 `package.json`，能推导出 `mvn test` / `pnpm build` 等）；
  2. 探测到的门禁命令**自动加入白名单**（现在要靠用户手动点"把门禁命令加入白名单"）；
  3. 门禁为空时，在面板引导卡**明确警告**："当前没有门禁，任务将无法完成验收"，并给一个"去配置门禁"的按钮。

**A4. 契约引用未定义门禁时，报错不告诉人怎么修**
- 现象：`UNKNOWN_GATE 断言 A1 引用了未定义的门禁 compile`。
- 影响：模型/用户不知道该去配置页加门禁，也不知道可以用 `command` 形式的断言。
- 建议：报错信息附上"当前可用门禁：…"，并提示"没有门禁时可改用 `check.command` 写命令断言"。

### B 级：能用但别扭（建议修）

**B1. 缺口页"对应"功能在新系统为空时形同虚设**
- 证据：`state.targetControllers = []`（新系统 0 控制器）→ "对应"输入框的候选列表是空的。
- 建议：候选为空时禁用"对应"，并提示"新系统还没有代码，先实现再重新盘点"。

**B2. 缺口"依据"显示 `none`，对从零重构的用户没有指导意义**
- 证据：`byBasis: { none: 23 }`，面板"依据 / 对应"列全是 `none`。
- 建议：新系统为空时显示"新系统暂无对应实现"，而不是内部术语 `none`。

**B3. "开始重构"只能复制指令，需要手工粘贴**
- 现象：点按钮只复制了一句话，用户可能不知道要粘贴到对话框。
- 建议：复制后弹出明确提示（"已复制，去对话框 Ctrl+V 发送"）；或复用"待办请求"机制（像技术选型咨询那样写进队列，模型下一轮自动处理）。

**B4. 技术选型"请模型给建议"点了没反应**
- 现象：提交后只是写了个请求，必须回对话说一句"处理技术选型请求"。
- 建议：提交后把提示做得更醒目（面板内浮动提示 + 引导卡提示）；或在引导卡里加一条"等待模型回答"的计数。

**B5. 进展反馈要手动两步**
- 现象：写完代码后必须点"盘点"再点"刷新缺口"，缺口才更新。
- 建议：面板加一个"刷新进度"按钮（盘点 + 重算缺口一次完成）；任务关闭后自动重算关联缺口。

**B6. 前端页面完全没有被跟踪**
- 现象：老系统有 78 个 Vue 文件，但缺口清单只有 23 个后端控制器，前端一行都没有。
- 影响：你的重构对象里有大量前端，插件却只看得见后端。
- 建议：把 `target.vuePages` / `routes` 也纳入缺口（至少按页面/路由维度出一个"前端缺口"分区）。
