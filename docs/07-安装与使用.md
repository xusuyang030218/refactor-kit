# RefactorKit 安装与使用

## 1. 安装（DSH Desktop）

DSH Desktop 的 `desktop` profile 由应用独占管理，命令行无法改动（会报 `managed exclusively by the Electron application`），必须在 DSH 窗口里安装：

1. 确认插件依赖已就绪（只需一次）：在本仓库目录执行 `npm install`。
2. DSH 左侧栏点 **插件**。
3. 点 **添加插件**，粘贴本仓库的绝对路径并回车：
   ```text
   D:\DTS\DSH-rebuild-tool
   ```
4. 预览应显示 **dsh-plugin-refactorkit（RefactorKit 重构工具箱）**，确认安装。
5. 安装后在 **已安装** 中能看到 RefactorKit 卡片。若卡片显示错误，把错误原文发给我。

> 这与 `dsh-session-viz`（`link:D:/dsh-session-viz`）的安装方式相同。插件以 `link:` 方式指向本目录：以后改了插件代码，重启 DSH 即可生效，无需重新安装。

其他 profile（web / tui / 自建）可以用命令行：`powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Profile web`。

## 1.1 一键导入（命令行，已实测）

DSH 插件页之外，也可以直接导入（效果与插件页"添加插件"相同，desktop profile 开启了 `patchReload: live`，**无需重启**）：

```powershell
node scripts\desktop-import.mjs            # 导入
node scripts\desktop-import.mjs --dry-run  # 只预览改动
node scripts\desktop-import.mjs --remove   # 卸载
```

它做三件事：在 profile 的 `node_modules` 下建立指向本仓库的 junction；在 `package.json` 的依赖与 bundles 中加入本插件；在 `pnpm-lock.yaml` 中插入对应记录。不运行 pnpm，不改动其他插件。
2026-10-09 实测：导入后运行中的 DSH 立即出现 14 个技能与 13 个 `rk_*` 工具，`rk_status` 调用正常。

> **面板（v0.2）需要重启一次 DSH**：面板包含新的 Host 路由与浏览器端模块，运行中的 DSH 不会热加载已安装包的新代码。完全退出 DSH（托盘图标 → 退出）再打开即可，之后改插件代码也是"重启生效"。

## 2. 第一次使用（RefactorKit 面板）

所有配置与审核都在 **右侧栏的 RefactorKit 面板** 里完成，不再一问一答。

1. 新建会话，工作目录选择新系统仓库，例如 `D:\DTS\DTS-rebuild`。
2. 打开右侧栏（会话右上角的展开按钮）→ 点 **+** → 选 **RefactorKit 重构**。
3. 面板识别到未初始化，显示 **初始化向导**：
   - 新系统仓库：已自动填好当前会话目录；
   - 老系统仓库：填 `D:\DTS\d2d-ncore-cuc-datadiscover-repository`；
   - 点 **探测并生成草稿**，下方出现配置表单：写入范围、模型槽（下拉选择你在「设置 → 模型」中配好的模型）、门禁表、命令白名单、审核预设；
   - 检查后点 **保存并初始化**（等同 CP0 审核通过）。
4. 到 **概览** 点 **盘点新旧仓库**，再点 **刷新缺口**。
5. 到 **缺口** 核对类名对应：依据为 name / alias 的是推断出来的，不对的点 **对应** 改正；确定不迁移的点 **裁撤** 并写理由。
6. 回到对话说你的意图，例如："把 G-DataFormController 做完"。模型推进到需要你签字的节点时，**面板自动打开到「待审核」**，模型在后台等你：
   - 可编辑块（契约、类名对应等）直接在面板里改，点 **通过**（改过会显示 **修改后通过**）；
   - 不同意写意见点 **提意见退回** 或 **驳回**；
   - 关键决策（CP3）、阻塞上报（CP6）显示为方案按钮，直接点选。
7. 不阻塞的待阅材料（如审查结果）在「待审核」下半部分，看完点 **已阅**。

配置随时可在面板 **配置** 页修改，保存时会校验，有错误不会写入；文件里的注释与其他字段保留。

> 没有打开 Web 界面时（例如 headless 运行），审核会回退为对话中的问答卡。可在配置页「审核方式」中固定为 panel 或 card。

## 3. 你会在哪些地方审核

| 审核点 | 什么时候出现 | 你做什么 |
|---|---|---|
| CP0 项目配置 | 初始化 | 确认写入范围、门禁、模型槽 |
| CP1 缺口清单 | 首次生成缺口；申请裁撤功能 | 核对类名对应；同意 / 拒绝裁撤 |
| CP2 任务契约 | 打开任务（高风险时阻塞） | 确认验收标准，可直接改断言 |
| CP3 关键决策 | 模型遇到返工成本高的选择 | 选方案 |
| CP4 审查结果 | 另一家模型审查完 | 标记"接受风险 / 误报"（默认不阻塞） |
| CP5 交付验收 | 代码底线都满足后（高风险时阻塞） | 签收或退回 |
| CP6 阻塞上报 | 连续失败或超预算 | 继续 / 调整契约 / 放弃 |

审核密度在 `refactorkit.yaml` 的 `review.preset` 中切换：`strict`（每个都等你）/ `standard`（默认）/ `light`。

## 4. 进度与产物

- 说"看进度"：生成并打开 `.refactorkit/report.html` 看板。
- 所有审核材料：`.refactorkit/review/`（每个任务一个目录，`log.md` 是时间线）。
- 所有证据原文：`.refactorkit/evidence/`。
- 建议在新系统仓库的 `.gitignore` 中加入 `.refactorkit/evidence/`（证据可能较大）；审核材料与 `tasks.json` 可以提交，便于团队复核。

## 5. 卸载与回滚

- 卸载：插件页 → RefactorKit → 卸载。项目中的 `refactorkit.yaml` 与 `.refactorkit/` 保留，可手动删除。
- 安装前的 profile 备份：`D:\DTS\DSH-rebuild-tool\.profile-backup\<时间戳>\`（`package.json`、`pnpm-lock.yaml`、`cordis.patch.yml` 等）。正常卸载不需要用到它。

## 6. 常见问题

| 现象 | 处理 |
|---|---|
| 右侧栏 + 里没有 RefactorKit | 重启 DSH（新版本的浏览器端模块在启动时加载） |
| 面板显示"无法确定当前会话的工作目录" | 在打开了项目目录的会话中使用；空白会话没有工作目录 |
| 面板一直"读取项目…" | 刷新页面；仍不行把面板中的报错原文发给我 |
| 输入 `/` 看不到 refactorkit | 新开一个会话（技能目录在会话开始时生成）；仍没有则重启 DSH |
| 工具报"没有 refactorkit.yaml" | 会话工作目录不是新系统仓库；或先 `/refactorkit` 初始化 |
| 门禁 `exec=env-failed` | 命令在本机不可用（如缺 JDK / mvn），不是项目失败；在 CP2 改用本机能运行的检查 |
| `rk_review` 报"所有候选都与实施者同源" | 在 `slots.reviewer.candidates` 中加入与主会话不同 provider 的模型 |
| 写文件被拒："不在 writeScope 内" | 有意的保护；需要改哪个目录，请在 `refactorkit.yaml` 的 `project.writeScope` 中加入 |
