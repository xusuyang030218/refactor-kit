# RefactorKit 入口设计

> 版本：v3.3（2026-10-09）｜ 需求【已确认】："进入的位置你重新进行设计"
> 所有 DSH 机制均已对照 DSH Desktop 2.0.17 构建产物确认

---

## 0. 一页结论

用户从"装上插件"到"推进第一个缺口"，只经过 **4 个入口**，每个入口只做一件事：

```text
① 安装入口          ② 对话入口               ③ 项目入口                  ④ 进度入口
scripts/install.ps1 ─► 输入 /refactorkit ─► 未初始化：rk_init ─► CP0 审核 ─► 写 refactorkit.yaml
（一次性）            （任何时候）           已初始化：rk_status ─► 告诉你"现在在哪、下一步是什么"
                                                                          └► report.html 看板
⑤ 命令行入口（无 DSH / CI）：node bin/rk.mjs init | survey | gaps | gate | truth | report | status
```

设计原则：
1. **只记一个命令**：`/refactorkit`。不论项目处于什么状态，它都会先判断"你在哪"，再给出下一步。
2. **配置也要审**：`refactorkit.yaml` 决定了写入范围、门禁命令和老仓位置，所以初始化本身是一个审核点（**CP0**）。
3. **未初始化不报错**：所有 `rk_*` 工具在找不到配置时，返回"请先 `/refactorkit` 或 `rk_init`"，不抛异常。

---

## 1. 入口 ①：安装

| 方式 | 命令 / 操作 | 说明 |
|---|---|---|
| 脚本（推荐） | `powershell -ExecutionPolicy Bypass -File scripts\install.ps1` | 读取 `$env:DSH_PROFILE`（默认 `desktop`），执行 `dsh plugin --profile <p> add "dsh-plugin-refactorkit@link:<仓库绝对路径>"`；先打印将执行的命令，确认后再执行 |
| 手动 | 同上命令 | 适合 CI 或已有 dsh CLI 的环境 |
| 卸载 | `powershell -ExecutionPolicy Bypass -File scripts\uninstall.ps1` | `dsh plugin --profile <p> remove dsh-plugin-refactorkit` |

插件形态：
- `package.json` 声明 `dsh.bundle.patch: ./cordis.patch.yml`，补丁插入一行 `id: refactorkit`。
- 纯 ESM JavaScript，**无构建步骤**。DSH 官方说明：Host-only bundle 不需要构建工具；这样也避开了"本地包未构建导致加载器崩溃"的已知问题。
- 唯一运行时依赖：`yaml`（解析 `refactorkit.yaml`）。
- 显示信息放在 `locale/zh.json`、`locale/en.json` 和 `icon.svg`，会出现在 DSH 插件管理页。

## 2. 入口 ②：对话入口 `/refactorkit`

插件通过 `ctx.skills.register()` 注册一个**用户可调用、模型也可调用**的技能 `refactorkit`。在 DSH 输入框键入 `/` 即可在建议列表中看到它（`dsh-client-ui-skill`：用户可调用的技能以 `/name` 调用）。

用法：

| 输入 | 效果 |
|---|---|
| `/refactorkit` | 判断项目状态，给出"现在在哪、下一步" |
| `/refactorkit 把缺口 A3 做完` | 判断状态后直接进入该任务 |
| `/refactorkit 看进度` | 生成并打开看板 |

技能正文是一张**状态路由表**，而不是固定流程：

| 项目状态（由 `rk_status` 返回） | 建议的下一步 |
|---|---|
| `uninitialized`：找不到 `refactorkit.yaml` | `rk_init`：探测技术栈，起草配置，触发 CP0 |
| `no-survey`：已初始化但未盘点 | `rk_survey`，然后 `rk_gaps` 生成缺口清单，触发 CP1 |
| `pending-review`：有阻塞中的审核点 | 列出待审项，提醒用户处理 |
| `ready`：有缺口、没有进行中的任务 | 按用户意图选缺口，`rk_task_open` |
| `in-progress`：有 OPEN 任务 | 报告该任务缺哪几条底线，继续推进 |
| `blocked`：有 BLOCKED 任务 | 展示 CP6 内容，等用户决定 |

模型拿到路由表后，**怎么做仍由它自己决定**；技能只告诉它"现在在哪"。

## 3. 入口 ③：项目入口 `rk_init`（新增审核点 CP0）

`rk_init` 的流程：

1. **探测**（纯代码，无模型）：
   - 目标仓库 = 会话工作目录（`exec.agent.session.header.cwd`），或参数 `targetRoot`；
   - 技术栈：`pom.xml`（Maven / Spring Boot 版本）、`package.json` / `pnpm-workspace.yaml`（Vue / Vite 版本）、`db/migration`（Flyway）；
   - 顶层模块列表，作为 `writeScope` 草稿；
   - 门禁草稿：发现 Maven → `mvn -q test`；发现 pnpm workspace → `pnpm -r build`、`pnpm -r typecheck`；发现 `tests/*.ps1` → 冒烟脚本（标为 `sideEffect: true`）；
   - 老仓：参数 `legacyRoot`（必填；没有时让模型询问用户）。
2. **起草**：生成 `refactorkit.yaml` 草稿，写入 `.refactorkit/review/CP0-config.md`（YAML 放在可编辑代码块中）。
3. **CP0 审核**（始终 `block`）：审核卡列出老仓路径、写入范围、门禁命令（标出哪些有副作用）、模型槽、审核预设。
4. **落盘**：通过后，读取（可能被用户改过的）代码块，校验后写入 `<targetRoot>/refactorkit.yaml`；并在 `.gitignore` 中建议忽略 `.refactorkit/evidence/`。

| 审核点 | 触发 | 内容 | 策略 |
|---|---|---|---|
| **CP0 项目配置** | `rk_init` | 老仓路径（只读）、写入范围、门禁命令与副作用标记、命令白名单、模型槽、审核预设 | 始终 `block`；无应答时不写配置 |

---

## 4. 入口 ④：进度入口

| 入口 | 形式 |
|---|---|
| `rk_status` | 工具结果：项目状态、缺口统计、任务列表（状态 / 风险 / 底线缺项）、待审核项、建议下一步 |
| `rk_report` | 生成 `.refactorkit/report.html`（单文件，双击即开），并提示用 `present` 展示 |
| 审核文件目录 | `.refactorkit/review/`，按任务分目录，`log.md` 记录时间线 |

---

## 5. 入口 ⑤：命令行（无 DSH 或 CI）

```text
node bin/rk.mjs init   --legacy <老仓> [--target <新仓>]   # 只生成草稿，不经审核卡；需人工检查后改名生效
node bin/rk.mjs survey [--target <新仓>]                  # 写 .refactorkit/facts.json
node bin/rk.mjs gaps                                      # 写 .refactorkit/gaps.json，打印摘要
node bin/rk.mjs gate   <门禁名...>                        # 执行命名门禁，打印证据
node bin/rk.mjs truth  --self-reported 1.0                # 自报 vs 实测仲裁
node bin/rk.mjs report                                    # 生成 report.html
node bin/rk.mjs status                                    # 同 rk_status
```

CLI 与插件共用 `src/core/`；CLI 不触发审核卡（没有 DSH 界面），`init` 只写草稿 `refactorkit.draft.yaml`。

## 6. 工具清单（最终）

| 工具 | 入口角色 | 审核点 |
|---|---|---|
| `rk_status` | 进度入口；`/refactorkit` 的第一步 | — |
| `rk_init` | 项目入口 | CP0 |
| `rk_survey` | 盘点 | — |
| `rk_gaps` | 缺口清单 | CP1 |
| `rk_task_open` | 打开任务 | CP2 |
| `rk_decide` | 关键决策 | CP3 |
| `rk_delegate` | 临时分身 | — |
| `rk_review` | 异源审查 | CP4 |
| `rk_gate` | 门禁与证据 | — |
| `rk_truth` | 真相仲裁 | — |
| `rk_task_close` | 关闭任务 | CP5 / CP6 |
| `rk_note` | 项目记忆 | — |
| `rk_report` | 看板 | — |

与 01 文档相比：新增 `rk_status`、`rk_init`；`rk_next`（guided 档位建议）合并进 `rk_status` 的"建议下一步"；`rk_skill`（技能工坊）推迟到 P2。
