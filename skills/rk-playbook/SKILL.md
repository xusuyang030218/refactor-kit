# RefactorKit 全局地图

## 一句话
放开过程，守住结果。你自主决定怎么做；插件用代码检查"做完没有"，用户在关键节点签字。

## 底线（代码强制，绕不过去）
| # | 底线 | 何时要求 |
|---|---|---|
| ① | 契约中每条断言都有 **pass** 证据（`rk_gate` 产生） | 所有任务 |
| ③ | 真相仲裁不是 FALSE_CLAIM（`rk_truth` 或 `rk_task_close` 带 `selfReported`） | 风险 L1、L2 |
| ② | 至少一次**异源**审查通过（`rk_review` 自动选不同 provider） | 风险 L2 |
| ④ | 只写 `writeScope`；老仓只读；`.refactorkit/` 只能经 rk 工具改 | 始终 |
| ⑤ | 不可逆命令（写库、push、装依赖、flyway migrate）与有副作用门禁需用户审批 | 始终 |
| ⑦ | 同一断言连续失败 3 次、关闭被拒 5 次、超预算 → 任务 BLOCKED 交给用户 | 始终 |

## 风险分级（关闭时按实际 diff 计算，你说了不算）
- **L0**：≤2 个文件，且只是文档、样式、文案 → 只要证据。
- **L1**：常规代码改动 → 证据 + 仲裁。
- **L2**：Controller / 路由 / 接口签名、迁移脚本或 `.sql`、鉴权代码（StpUtil、@SaCheck）、依赖清单、跨 ≥2 个顶层模块 → 再加异源审查。

## 人工审核点（用户签字的地方）
CP0 项目配置 · CP1 缺口清单与裁撤 · CP2 任务契约 · CP3 关键决策（`rk_decide`）· CP4 审查结果 · CP5 交付验收 · CP6 阻塞上报。
审核卡被驳回或给出意见时：**照意见修改再提交，不要自己判定"其实可以"。** 用户关闭审核卡表示想直接说话，停下来等。

## 什么时候分身（`rk_delegate`）
| 信号 | 建议 |
|---|---|
| 要读大量旧代码，但只需要结论 | 分身，`lens=archaeologist`，`tools=read-only`，`slot=fast` |
| 需要独立第二意见 | `rk_review`（会自动换一家模型） |
| 几个互不依赖的子任务 | 并行分身 |
| 任务连贯、上下文已在手 | **不要分身**，直接做 |
分身看不到你的上下文：`task` 里要写全背景、范围和期望输出。

## 写契约
断言要能被命令判定：优先引用 `refactorkit.yaml` 中的门禁（`check.gate`），需要更细时写白名单内的命令（如 `mvn -q -Dtest=XxxTest test`）。详见 `rk-contract-writing`。

## 常见失败模式
- 自报 100% 但关联缺口覆盖率低 → FALSE_CLAIM。先看 `rk_gaps list`，确认缺口里的端点都实现了。
- 门禁 `exec=env-failed`（命令不存在、JDK 缺失、沙箱拦截）→ 这是环境问题，不是项目失败；告诉用户，不要伪造通过。
- 改了 writeScope 外的文件被拒 → 不要绕路；请用户调整配置或换实现方式。
- 关闭被拒后反复提交同样内容 → 会触发 BLOCKED。先读清缺哪条。
