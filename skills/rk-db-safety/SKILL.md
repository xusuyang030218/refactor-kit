# 数据库变更安全

## 写之前
- 确认目标数据库类型与版本（如 PostgreSQL 15 / MySQL 8），SQL 方言只写这一种。
- 确认表结构：从迁移脚本或现有 DDL 中查，不凭记忆写列名（见 `rk-evidence-first`）。

## 每条高危语句必须附带
| 项 | 内容 |
|---|---|
| 风险等级 | 低（加列可空、加索引）/ 中（改类型、加非空约束）/ 高（删列、删表、批量更新删除） |
| 前置条件 | 数据量、锁表影响、是否需要停机窗口 |
| 回滚方案 | 对应的逆向语句或备份恢复步骤 |
| 验证方式 | 执行后用什么查询确认结果 |

## 执行
- 在数据库上执行写操作会触发 RefactorKit 的不可逆操作审批，等用户确认。
- 先在测试环境执行并验证；生产环境由用户自己操作。
- 不要在同一条命令中混合 DDL 与大批量 DML。

## 迁移脚本
参见 `rk-mybatis-flyway`：已发布的脚本不可修改，版本号不可复用。
