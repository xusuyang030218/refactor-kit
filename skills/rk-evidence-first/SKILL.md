# 证据优先

## 规则
1. **先查再写**：接口路径、请求/响应字段、枚举值、错误码、表名列名，必须在仓库中找到出处（文件 + 行号）后再使用。
2. **查不到不编**：找不到时写 `TODO(待确认: <问题>)`，并在任务 summary 和 `rk_note({ kind: "fact" })` 中记录；关键处用 `rk_decide` 请用户定。
3. **推断要降级**：只能靠命名推测的，在实现说明里标"推断"，审查时会被重点核对。

## 查找顺序
1. 新仓同模块的相邻代码（同类 Controller / Service / 组件的写法）
2. 新仓的接口定义、DTO、Flyway 脚本
3. 老仓对应实现（只读；可分身 `archaeologist` 读）
4. 项目文档（`memoryFiles` 中列出的索引与词汇表）

## 常见编造
- 想当然的字段名（`userName` vs `username`）
- 不存在的工具方法（`StringUtils.isBlank` 来自哪个包？）
- 把老系统的接口路径照搬到新系统（新系统已经是 REST 风格）
- 枚举值顺手加一个（应先确认数据库与前端是否支持）
