# 读老代码

## 原则
- 老仓**只读**（插件会拦截写入）。结论必须带出处：文件路径 + 行号或类名.方法名。
- 只为当前任务读：先定问题（"导出功能的数据从哪来、权限怎么校验"），再读。

## 找功能边界
1. 从入口反查：菜单配置表 / 路由配置 → Controller → Service → DAO / Mapper。
2. 从权限反查：权限码、菜单 id 在代码中的使用处，常常暴露"同一功能的多个入口"。
3. 从数据反查：涉及的表名在 Mapper XML 和存储过程中的所有出现。

## 容易漏掉的隐藏逻辑
- 拦截器 / 过滤器 / AOP：租户隔离、数据权限、审计日志常在这里。
- 前端拼接的 SQL 片段或查询条件（老系统 JS 中常见）。
- 存储过程、视图、触发器。
- 定时任务里的数据加工。
- 配置文件中的开关与魔法值。

## 只有 class 没有源码时
用反编译工具补源码到临时目录（不要放进新仓），结论中注明"来自反编译"。

## 输出格式（分身时要求这样返回）
- 功能边界：入口列表
- 数据流：表 → 处理 → 输出
- 隐藏逻辑：逐条带出处
- 不确定点：需要用户确认的
