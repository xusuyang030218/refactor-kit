# 测试策略

## 选型
| 类型 | 适用 | 典型命令 |
|---|---|---|
| 单元测试 | Service / Mapper 逻辑、工具类、边界与异常分支 | `mvn -q -Dtest=XxxServiceImplTest test` |
| 接口测试 | Controller 路径、参数校验、返回结构、鉴权 | MockMvc 单测，或项目的冒烟脚本 |
| UI 测试 | 页面交互、跨页流程 | 项目已有 E2E 脚本；没有时以构建 + 组件单测替代并标注 |

## 规则
- **真实执行**：断言对应的测试必须真的跑过，不能以"代码看起来对"代替。
- **全量执行**：选定的测试类 / 脚本中的用例全部执行，不挑通过的跑。
- **三路覆盖**：新增逻辑至少覆盖正常、边界、异常三种情况。
- **覆盖率标注**：核心模块分支覆盖率低于 80% 时在任务 summary 中写明。

## 有副作用的测试
冒烟脚本、接口测试常会创建或删除业务数据，在配置中应标 `sideEffect: true`，运行前会请用户审批。不要为了绕过审批改用其他命令。

## 跑不起来时
依赖数据库或外部服务的测试在本机跑不起来：记录为环境问题（`exec=env-failed`），在 CP2 契约中改用可在本机运行的检查，并让用户确认。
