# 审查维度

## 按风险分配阅读深度
| 文件类型 | 读法 |
|---|---|
| 配置、启动入口、Controller / API 层、鉴权、迁移脚本 | 完整阅读 |
| Service、页面组件 | 按 diff 阅读，遇到疑点再看上下文 |
| 样式、类型声明、生成代码 | 跳过或 grep 关键词 |
| 跨文件关联 | 用搜索确认调用方与被调用方 |

## 质量
- 是否兑现契约中的每条断言；有无"看起来实现了"的空壳（TODO、写死返回、吞异常）。
- 异常与错误码是否走项目统一规范；参数校验是否齐全。
- 是否顺手改了无关代码（范围蔓延）。

## 性能
- 循环内查库（N+1）、无分页的全表查询、无索引的大表条件。
- 一次性加载大文件 / 大结果集到内存。

## 安全
- SQL 拼接（应参数化）；动态排序字段是否白名单。
- 鉴权：新接口是否有登录 / 权限校验；租户隔离是否遗漏。
- 敏感数据：日志中打印密码、令牌、个人信息；导出是否脱敏。

## 架构
- 分层是否正确（Controller 不写业务、Service 不直接处理 HTTP 细节）。
- 是否跨模块直接引用内部实现；新增依赖是否必要。

## 严重度
- **blocker**：功能错误、安全漏洞、数据风险、契约未兑现 → verdict 必须 reject。
- **major**：明显缺陷但不致命（缺少校验、性能隐患）。
- **minor**：风格、命名、可读性。
