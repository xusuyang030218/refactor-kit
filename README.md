# RefactorKit · 自主编排的 DSH 重构插件

> **放开过程，守住结果。**
> 让模型自己决定用哪个技能、要不要分身、分身用哪家模型；插件只用代码守住几条底线：证据、异源审查、真相仲裁、写入范围。

状态：**设计阶段**（代码未开始）｜ 宿主：DeepSeek Harness（DSH）Desktop 2.0.17 ｜ 案例项目：DTS 重构（`D:\DTS\DTS-rebuild`）

## 它解决什么问题

用 AI 重构老系统时，有两个反复出现的问题：

1. **AI 说"完成了"，但实际没完成**。DTS 案例中出现过两次：自报 100%、复查 16%；自报 100%、实测 46.9%。
2. **固定分身拖累强模型**。原来用 AiDO 组织了 7 个岗位分身，流程和工具边界都是固定的。弱模型需要这种护栏，强模型却被迫在分身之间来回搬运上下文。

## 核心设计

| 层 | 做法 | 谁决定 |
|---|---|---|
| 技能 | 按需加载的知识卡（迁移坑点、规范、方法），不规定步骤 | 模型 |
| 分身 | 随用随建的临时视角 + 指定模型 + 可选只读，用完即弃 | 模型 |
| 自主度 | `free` / `assisted` / `guided` 三档，按模型自动切换 | 配置 |
| **底线** | 关闭任务必须有证据；仲裁不能是虚报；高风险改动必须经过异源审查；写入范围、命令白名单、不可逆操作审批、账本保护 | **代码强制** |
| 检查强度 | 按改动风险 L0 / L1 / L2 分级，由 diff 事实计算：改文案只需构建通过，动接口、迁移脚本、鉴权才要求换家模型审查 | **代码计算** |
| **人工审核** | 6 个审核点：缺口清单、任务契约、关键决策、审查结果、交付验收、阻塞上报。审核卡在右侧边栏展开，审核文件可直接编辑 | **你** |

## 计划中的使用方式（实现后）

```powershell
# 1. 在 DSH profile 的 cordis.patch.yml 中挂载插件
#    - insert: [{ id: refactorkit, name: dsh-plugin-refactorkit }]
# 2. 在目标仓库根目录放 refactorkit.yaml（从 templates/ 复制，改 project / gates）
# 3. 在 DSH 中对话：「把缺口 A3 做完」
# 4. 没有 DSH 时，也可以用 CLI：
node bin/rk.mjs survey
node bin/rk.mjs gate --task T-07
node bin/rk.mjs truth --self-reported 1.0
```
